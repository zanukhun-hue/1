# Магазин @null_object_ae_bot

Бот используется только для продажи пресетов. Старые статистика, модерация и ручное подтверждение оплаты удалены. `/start` убирает прежнюю клавиатуру и открывает магазин. Команды: `/packs`, `/myorders`, `/help`, `/paysupport`, `/terms`. Каждый из девяти наборов стоит **100 Telegram Stars**, общая цена сайта и бота задана в `preset-products.js`.

## Запуск

1. Выполнить `supabase_schema.sql`, затем `preset-sales-schema.sql` в SQL Editor проекта Supabase. Второй файл создаёт постоянные счета/покупки и **приватный** бакет `paid-presets`. Публичных политик для платных архивов нет.
2. Загрузить в этот бакет девять ZIP: `shakes.zip`, `color.zip`, `distortion.zip`, `glow.zip`, `text.zip`, `frames.zip`, `speed.zip`, `glitch.zip`, `effects.zip`.
3. В Render нужны `TELEGRAM_BOT_TOKEN` именно этого бота, `TELEGRAM_WEBHOOK_SECRET`, `SUPABASE_URL`, `SUPABASE_ADMIN_KEY` либо `SUPABASE_SERVICE_ROLE_KEY`. `TELEGRAM_CHAT_ID` — личный чат владельца для поддержки. Значения токенов и серверных ключей не должны попадать в Git.
4. Выполнить Deploy latest commit. Бот принимает обновления на существующем `/api/telegram/webhook`. Обработчик отвечает успехом после обработки события; ошибка сохранения оплаты или выдачи приводит к повторной доставке обновления Telegram.
5. `pwsh -File tools/setup-preset-bot.ps1` обновляет профиль и меню команд. Скрипт берёт токен из окружения или зашифрованного Windows DPAPI-файла вне репозитория. Для обновления webhook: тот же скрипт с `-ConfigureWebhook`, при этом в окружении должен быть **тот же** `TELEGRAM_WEBHOOK_SECRET`, что в Render. Нужные типы обновлений: `message`, `callback_query`, `pre_checkout_query`. Секрет webhook скрипт самостоятельно не меняет.

На ПК архивы восстановлены из Git-версии `db3f54f^` в `C:/Users/zanuk/.codex/private-assets/null-object-ae/paid-presets/`: 113 .ffx в девяти ZIP, размеры проверены по каталогу, целостность ZIP проверена. Команда воспроизведения: `python tools/prepare-paid-presets.py --ref "db3f54f^" --output PRIVATE_DIRECTORY`. Папка должна находиться вне репозитория.

После установки серверного ключа в окружение загрузка с проверкой размера доступна через `node tools/upload-paid-presets.cjs PRIVATE_DIRECTORY`. Ключ передаётся только Supabase. Архивы не коммитятся и не выдаются через `/assets` или `/preset-download`.

## Покупка и выдача

Перед выставлением счёта бот показывает условия, проверяет доступность ZIP и сохраняет счёт в БД. Цена, покупатель и набор проверяются при pre-checkout и событии `successful_payment`. До подтверждения оплаты ZIP не отправляется. Один платёж имеет один заказ; выдача захватывается условным обновлением в БД, чтобы параллельные копии webhook не отправляли архив одновременно. При ошибке заказ сохраняется для повторной выдачи. Если процесс прервался во время отправки, захват можно повторить через пять минут. После неопределённого сетевого результата повторная отправка файла возможна — подтверждение Telegram и обновление БД не являются общей транзакцией.

«Мои покупки» показывает только покупки пользователя и позволяет повторно получить ZIP по Telegram `file_id`. Возвращённые платежи отмечаются по `refunded_payment`, повторное скачивание для них закрывается. Команда `/paysupport <описание>` передаёт обращение владельцу; возврат средств владелец рассматривает отдельно. Реальных возвратов код автоматически не выполняет.

Проверка `npm run test:shop` использует PostgreSQL в памяти и подменённые Telegram/Storage, без списания Stars и отправки сообщений реальным покупателям. Проверены цена, условия, недоступный архив, другой покупатель, неверная сумма, повтор платежа, перезапуск, возврат, повторная выдача после ошибки и запрет публичного чтения таблиц. Проверка не подтверждает настройку рабочего Supabase или реальный платёж.

[Документация Telegram Stars](https://core.telegram.org/bots/payments-stars).
