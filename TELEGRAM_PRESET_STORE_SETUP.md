# Telegram-бот: продажа пресетов (дополнение к существующему боту)

Сайт использует тот же `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `TELEGRAM_WEBHOOK_SECRET` через уже существующий маршрут `/api/telegram/webhook`. **Не создавайте нового бота.**

## Настройка на Render

1. Установите `TELEGRAM_BOT_URL=https://t.me/USERNAME_ВАШЕГО_БОТА` (точное имя из BotFather, **не канал и не личный профиль**).
2. Проверьте, что существующие `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET` заданы.
3. Чтобы бот отправлял оплаченные архивы, сначала отправьте боту девять ZIP из частного архива **в чат с ботом**. Получите реальные `file_id` каждого документа из Telegram Bot API (например, временно через безопасный webhook-лог; никогда не публикуйте токен или ZIP).
4. Задайте на Render переменные:
   `PRESET_FILE_ID_SHAKES`, `PRESET_FILE_ID_COLOR`, `PRESET_FILE_ID_DISTORTION`, `PRESET_FILE_ID_GLOW`, `PRESET_FILE_ID_TEXT`, `PRESET_FILE_ID_FRAMES`, `PRESET_FILE_ID_SPEED`, `PRESET_FILE_ID_GLITCH`, `PRESET_FILE_ID_EFFECTS`.
5. Сделайте тестовый заказ и подтвердите выдачу с администраторского аккаунта.

## Как работает

Сайт открывает ссылку `https://t.me/USERNAME?start=pack_color`; бот присылает заказ администратору (`TELEGRAM_CHAT_ID`). Администратор после **реальной проверки оплаты** нажимает «Выдать ZIP». Бот отправляет покупателю архив через Telegram `file_id`. Бесплатные плагины сайта не затронуты.

**Ограничения текущей версии:** заявки хранятся в памяти процесса и пропадают при рестарте Render; перед реальными продажами требуется постоянная база данных заказов и идемпотентная обработка обновлений Telegram. Сам бот не принимает рублёвые платежи и не подтверждает их автоматически. Для цифровых товаров оплата внутри Telegram осуществляется через **Telegram Stars (XTR)**; если нужна встроенная оплата, отдельно подключите Stars и получайте событие `successful_payment`. Не заполняйте `file_id` публичными ссылками на ZIP.

**Безопасность:** Не выгружайте платные ZIP в общедоступный GitHub. Их старые версии могут оставаться в Git history. Для полноценной защиты репозиторий нужно перенести на чистую историю.
